# hr_hospital — Odoo 19

Модуль Odoo розміщений у директорії `hr_hospital/` на один рівень нижче кореня репозиторію.

Я також розглядав варіант розміщення модуля безпосередньо в корені репозиторію, але відмовився від нього, оскільки технічна назва модуля Odoo визначається назвою директорії модуля. Після звичайного `git clone` назва директорії репозиторію може відрізнятися від `hr_hospital`, через що XML ID на кшталт `hr_hospital.some_record` можуть більше не посилатися на цей модуль коректно.

Через `ir.model.access.csv` я визначив дозволені операції на моделях: пацієнт має право читання, інтерн додатково отримує право редагування візитів, а адміністратор — повний доступ, включно з видаленням. Через `ir.rule` я обмежив доступ до конкретних візитів: пацієнт бачить власні, інтерн редагує свої, лікар — свої та візити своїх інтернів, а менеджер може переглядати всі. ACL перевіряються першими й задають максимальний набір дозволених операцій, після чого правила записів звужують доступ до записів і не можуть надати права, яких немає в ACL. Такий поділ відокремлює дозволені дії від доступних даних, а правило менеджера для всіх візитів застосовується лише до читання, щоб не розширювати успадковані права редагування.

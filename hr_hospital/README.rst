Hospital Automation — Odoo 19
================================================================================

Навчальний модуль Odoo School: лікарі, інтерни, пацієнти, історія призначень,
класифікатор хвороб, візити, звіти та щоденне скасування прострочених візитів.
Автор: Maksym Shelestiuk. Ліцензія: LGPL-3.

Встановлення
--------------------------------------------------------------------------------

Додайте корінь репозиторію до ``addons_path`` разом зі стандартними addons
Odoo 19. У шляху має бути лише одна копія ``hr_hospital``. Оновіть список
Apps та встановіть Hospital Automation. Залежності: base, mail, web.
Для наявної бази зробіть резервну копію і оновіть модуль через ``-u hr_hospital``.
Міграція 19.0.6.0.0 переводить стандартні назви довідників в англійський слот,
не змінюючи довільні користувацькі назви.

Групи та доступ
--------------------------------------------------------------------------------

Групи знаходяться в категорії Hospital через ``res.groups.privilege`` Odoo 19.
Ієрархія: Patient → Intern → Doctor → Manager → Admin.

* Пацієнт читає тільки власні візити, свою картку та історію призначень.
* Інтерн читає і редагує власні візити лікаря; успадковує читання своїх
  візитів як пацієнта, якщо також прив'язаний до картки пацієнта.
* Лікар додатково читає та редагує візити своїх інтернів; зв'язок із ментором
  без ознаки інтерна такого доступу не надає.
* Менеджер читає всі візити, але редагує лише візити, дозволені успадкованими
  ролями лікаря та інтерна. Видалення заборонено.
* Адміністратор модуля має CRUD усіх моделей, включно з видаленням завершених
  візитів. Це звичайна роль, а не superuser чи адміністратор Settings.
* Звичайний Internal User поза ієрархією не має доступу до моделей модуля.

ACL у ``security/ir.model.access.csv`` спочатку визначають дозволені операції
на моделі: читання, редагування візитів для інтерна та повний CRUD для Admin.
Після ACL правила ``ir.rule`` звужують набір доступних записів відповідно
до ``patient_id.user_id``, лікаря та його ментора; вони не можуть надати
операцію, якої немає в ACL. Групові правила об'єднуються через АБО, тому
правило менеджера «всі записи» діє лише на читання і не розширює запис.
Старі XML ID ACL збережені, а їх групи замінені, щоб оновлення не залишало
повного доступу на ``base.group_user``.

Довідники лікарів, кваліфікацій та хвороб доступні ролям лише для читання;
змінює їх Admin. Персонал читає картки пацієнтів та історію призначень.
Масове перепризначення лікаря доступне лише Admin. Звітні візарди доступні
Manager та Admin. Зовнішні ключі з ``ondelete='restrict'`` захищають пов'язані
дані: спочатку видаліть залежні записи. Обмеження завершеного візиту на
редагування з попередніх блоків залишаються чинними навіть для Admin.

Демо-користувачі
--------------------------------------------------------------------------------

Встановлюйте базу з ``--with-demo``. Логіни:
``hospital.patient``, ``hospital.intern``, ``hospital.doctor``,
``hospital.manager``, ``hospital.admin``. Кожен пов'язаний із карткою пацієнта
або лікаря. Паролі навмисно не зберігаються в модулі: встановіть локальні
паролі через Settings → Users → Change Password перед входом.
Не надавайте цим користувачам режим superuser під час перевірки прав.

Українська локалізація
--------------------------------------------------------------------------------

``i18n/uk_UA.po`` отримано через ``odoo.tools.translate.trans_export`` з
встановленого Odoo 19 — той самий механізм використовує Export Translation.
Після експорту заповнено ``msgstr`` зі збереженням посилань та ``module:``.
Назви хвороб і кваліфікацій мають ``translate=True``; вихідні XML англійські.
Ієрархічна назва хвороби обчислюється в поточній мові й не зберігає один
спільний текст для всіх мов.

Активуйте Ukrainian, оновіть модуль та оберіть мову користувача. Для нових
рядків повторіть Settings → Translations → Export Translation, PO,
Ukrainian, Hospital Automation; або використайте ``scripts/export_uk.py``
через Odoo shell. Заповнюйте переклади у згенерованому каталозі. Перевірте
поля, меню та назви хвороб у двох мовах. Незаповнених рядків у поточному
каталозі немає; стандартні переклади полів mail/base взято з Odoo LGPL-3.

Перевірки
--------------------------------------------------------------------------------

Запуск у виділеній тестовій базі::

    odoo-bin -d hospital_test -i hr_hospital --with-demo \
      --test-enable --test-tags=/hr_hospital --stop-after-init --no-http

Оновлення з тестами::

    odoo-bin -d hospital_test -u hr_hospital \
      --test-enable --test-tags=/hr_hospital --stop-after-init --no-http

Тести перевіряють вік, ознаку інтерна, заборону ментора-інтерна, ієрархію
хвороб, захист завершених візитів, права через ``with_user`` та переклад.
Набори мають лише ``post_install`` і явно вилучають ``at_install``.
Демо-тест попереднього блоку пропускається у базі без демо; основні тести
створюють власні записи. Підсумки запусків наведені в ``VERIFICATION.md``
у корені репозиторію.
